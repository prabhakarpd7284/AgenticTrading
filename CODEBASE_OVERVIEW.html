AlphaDesk · Agentic Trading System

AI-driven Indian market trading platform

Three trading workflows, two API surfaces, one risk gate. Django + LangGraph for the trading core, a v2 multi-tenant Django stack for the trader UI, and a React SPA on top. Talks to Angel One SmartAPI, in paper or live mode.

Capital ₹500,000 Mode paper (default) Markets NSE · NFO · BSE · BFO Broker Angel One SmartAPI LLM Claude (Anthropic) Lots NIFTY 65 · BANKNIFTY 30 · SENSEX 20

1 · What this is

AlphaDesk is an end-to-end intraday + swing trading system for the Indian markets. It combines three things:

  • A deterministic trading engine (the legacy trading/ package) — strategies, risk validation, broker integration, journaling.
  • An LLM agent layer using LangGraph + Claude — for trade planning (directional) and options-position management (straddle), with a deterministic guardrail (@RiskGuard) as the last gate.
  • A modern operator UI — React + Vite SPA over a v2 multi-tenant Django stack (Postgres, Channels for WebSockets, Celery for async order execution).

It supports three trading workflows in parallel:

Equity intraday

Directional trades

BUY/SELL plans on NSE cash, generated by the @DirectionalTrader LLM agent, validated by @RiskGuard, executed via Angel One.

Options

Short straddle

Sell ATM call + put on NIFTY/BANKNIFTY, then manage the position every 15–30 min: hold, close, hedge, or roll.

Options

Pyramid options

Aggressive momentum pyramiding on intraday NIFTY / BANKNIFTY / SENSEX options. Pure-Python, no LLM in the loop.

The legacy trading/ package owns all strategy logic and the deterministic risk engine. The v2 backend wraps it with a multi-tenant API layer; during the migration the legacy bridge on port 8001 exposes the seeded SQLite tables to the React UI through /api/v1/legacy/*. 6 · The Cascade — 6-stage pre-trade framework

The React SPA is organised around a 6-stage workflow. Each stage is a page; each page consumes a single API endpoint, and the stages cascade — a green light at stage N is required to act at stage N+1.

7 · Strategies

A · Directional equity LLM

LLM-driven plans for individual stocks. The planner reads market data + recent trade history (RAG), produces a structured plan (entry, SL, target, qty, confidence). @RiskGuard rejects ~30% of plans deterministically.

trading/graph/trading_graph.py · trading/agents/planner.py · trading/services/risk_engine.py

B · Short straddle LLM

Sells ATM CE + PE on NIFTY/BANKNIFTY for time decay. A management loop runs every 15–30 min: analyse P&L + delta + VIX, prompt Claude for HOLD / CLOSE / CLOSE_CE / CLOSE_PE / ROLL_* / HEDGE. Hard rules override the LLM (underwater → force CLOSE_BOTH, ROLL on expiry → reject).

trading/options/straddle/graph.py · analyzer.py · lifecycle.py · prompts.py

C · Pyramid options Deterministic

Aggressive momentum capture on 5-min option candles. Entry: 5 EMA + Bollinger Bands + RSI momentum aligned. Pyramids risk 80% of unrealized profit on each add. Trails SL at higher lows + 3-candle floor.

trading/pyramid/strategy.py · trading/pyramid/telegram.py

D · Intraday structure screener Deterministic + LLM confirm

Real-time 5-min pattern detection: ORB (open-range breakout), VWAP fade, level bounce, level retest, swing high/low. Premarket scanner builds a watchlist from prior-day OHLC; LLM confirms each fire.

trading/intraday/{scanner,structures,levels,monitor,agent}.py · trading/screener/engine.py

E · Oliver Kell swing cycles Deterministic

Daily/weekly cycle phase detection — 8 phases (RE · WP · EC · BB bullish, EX · WD · EC_BEAR · BB_BEAR bearish). Actionable phases + trend alignment = high-conviction swing trades. Walk-forward backtester validates phase timing.

trading/swing/ok_cycles.py · ok_scanner.py · ok_backtest.py

F · Morning basket Deterministic

Premarket mood (BULLISH / NEUTRAL / BEARISH) drives 3–5 correlated leg signals. Manages SL with 5 EMA trail; breakeven at +0.5R; pyramids winners; closes all at 15:15 EOD.

trading/basket/manager.py · mood.py · signals.py · executor.py

DB routing

backend/apps/common/db_router.py:LegacyRouter pins every model with app_label=="trading" to the legacy alias (SQLite at repo root db.sqlite3); everything else stays on default (Postgres in dev/prod, in-memory SQLite in tests). Cross-DB relations are rejected — there is no JOIN across the boundary.

Settings caveat. The legacy bridge process (config.settings.legacy, port 8001) still needs the v2 default DB so JWT auth + tenant lookups work. It just narrows ROOT_URLCONF to config.urls_legacy so only /api/v1/legacy/* + auth + health are served from that process.

14 · Key invariants (never break these)

  1. @RiskGuard is the last gate before every order — paper or live. No bypass, no override.
  2. TRADING_MODE=paper is the default. Live is opt-in and explicit.
  3. Position sizing is deterministic (% of capital). The LLM never touches it.
  4. Every decision is journaled — including rejected trades.
  5. Audit-log failures never block trading — non-blocking writes.
  6. Expiry-day options must close before 15:15 IST — gamma risk explodes after.
  7. Short straddle hard stop — if combined premium > 1.3 × what was sold, close immediately.
